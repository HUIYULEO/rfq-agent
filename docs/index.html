MatrixNEXT RFQ Agent

航空备件询价处理智能体：四种输入、确定性定价、人工闸门、客户模板草案。

打开可运行智能体 https://rfq-agent-xk2m.onrender.com

文档版本 1.0 ｜ 产品版本 0.1.0 ｜ 2026-11-10 ｜ 运行环境 Python 3.11+（实测 3.12.9）

摘要

MatrixNEXT RFQ Agent 接收客户发来的询价邮件（正文表格、Excel 附件或 PDF 表单），输出两份交付物：一份按客户模板填写的报价草案，一份逐行说明报价依据的询价分析报告。

系统将可验证的解析与计算交给确定性引擎，将不可让渡的商业判断交回具名的人。报价单上的每一个数字都能回溯到原始文件的单元格；没有价格依据的行不给估值，而是转人工询价并写明原因。

1 问题定义

1.1 业务场景

航空备件供应商收到航空公司或维修厂的询价（RFQ）后，需在 1–2 个工作日内回复包含单价、金额、交期、件状与证书要求的报价单。这项工作包含四个环节：

  1. 行项目提取：从邮件正文或附件中取出料号、数量、单位、件状、截止日期。客户使用的列名与格式不统一，同一批客户前后两封邮件可能分别是正文表格、Excel 附件与 PDF 表单。
  2. 件状与合规判断：客户要求全新件（FN）、可服务件（SV）或大修件（OH），供应商现货可能是另一种件状。是否接受替代件状，属于商业判断。
  3. 价格依据检索：内部物料成本表提供成本，价格资源表提供供应商报价。缺少依据时不能估算。
  4. 按客户模板出单：金额、大写、有效期与每行的件状、证书、交期必须齐全，缺项即被客户退回。

单封询价的行数从 7 行到 122 行不等，六封官方素材合计 300 行。

1.2 关键痛点

环节 现状 后果
格式 六封官方邮件使用四种载体：正文 HTML 表格、正文制表符、Excel 附件、PDF 表单 每封都要人工重新对齐列名；122 行的单约需 1–2 小时；错行直接导致报错价
依据 价格来自两张内部参考表，300 行素材中仅 128 行能命中 报价发出后无法回答"这行为什么这个价"，争议无法追溯
判断 MOQ 超额采购、件状放宽、无价格依据被压缩成同一个"填个数字"的动作 三类性质不同的决策被掩盖，事后无法区分是计算错误还是商业选择
模板 客户模板明细表只有 5 个固定行，而实际询价有 7、21、122 行 必须动态增行，手工处理容易破坏模板格式

1.3 设计目标

  1. 六封官方邮件（300 行）走同一条链路，行为一致；
  2. 每一行可回溯到「邮件 → 附件 → 表/页 → 行 → 列 → 原值」；
  3. 没有价格依据时返回空值并说明原因，不产生估算价格；
  4. 输出为可交付的客户模板 DOCX，且明确标注为待复核草案；
  5. 机器不代替客户做商业决定，人不需要重算数字。

2 解决方案

2.1 方案概述

四种输入归一到一套行项目结构，由确定性定价引擎完成候选装配与约束过滤，在需要商业判断处停下等待人工预审，最后填充客户模板并生成分析报告。

2.2 处理流程

客户邮件（正文 HTML 表格 / 正文制表符 / .xlsx / .pdf）
   │  载体识别与解析；每行写入 evidence{file, container, sheet, row, column, raw}
   ▼
统一 RFQ 结构：单据字段 + 行项目 + 客户随附要求
   ▼
定价引擎：候选装配 → 硬约束过滤（件状 / 证书 / 单位 / 件号 / 时效）→ 加成与比价 → 复核项
   ▼
逐行核查
   ├─ 契约校验：每行有结果、来源可追、金额 = q2(单价 × 数量)
   ├─ 业务规则：件号匹配、证书、单位、件状、报价截止，逐行记录结论
   └─ 单据质量：重复料号、单位混用、缺字段、截止日期异常
   ▼
存在阻塞项时停在 awaiting_review；人工作答后 revision 递增并重算受影响的行
   ▼
询价分析报告 DOCX（每单必出） ＋ 报价草案 DOCX（可报价时）
   │  具名人工批准后，单事务写入历史报价表并生成正式文件

2.3 六步工作台

界面按处理流程分为六步，每一步的产物即为下一步的输入：

步骤 系统完成的工作 呈现内容
① 输入采集 锁定输入版本，识别载体、客户、询价号、评估日 原件链接、客户随附要求原文、模型理解结论、执行轨迹
② 结构提取 四种载体归一为行项目 每行料号、数量、单位、件状、截止日期、原始值、原件位置
③ 询价分析 查询数据快照、装配候选、执行硬约束 每行「有依据 / 待预审 / 阻断」、单价金额或原因、完整定位
④ 人工预审 生成阻塞项与可选动作 待预审卡片（问题、选项、依据、定位）与已通过记录
⑤ 分析报告 汇总处置结果与建议动作 已报价 / 待确认 / 转询价 / 不报价统计、逐行原因、规则核查结果
⑥ 报价草案 填充客户模板、计算金额大写、附加依据页 草案 DOCX 下载；启用演示策略时可执行批准入库

2.4 人机边界

系统负责 人负责
解析、归一、识别四种载体 决定无依据的行如何处理
按件状集合过滤候选、计算加成与比价 决定是否接受替代件状
标出重复料号、单位混用、日期异常 判断单据不一致是否影响本次报价
生成复核问题与明确选项 在给定选项中作出选择
填充模板、计算大写、编写依据页 对外发送前确认最终价格

2.5 关键设计决策

  1. 价格只有一个来源。 全部金额由 domain/pricing.py 的纯函数计算，模型仅参与理解与工具选择，不参与任何算术。对话助手获取的也是引擎结果，且载荷按页压缩，不传递完整行数据。
  2. 复核项按目标寻址。 复核项编号由目标推导（RI-0016 指第 16 行，RI-TASK 指整案），作答后不重新编号，决策日志始终指向同一对象；修改一个答案只重算受影响的行。
  3. 空结果不可被填充。 无价格依据时返回空值，小计显示 —；122 行均无依据的单据只生成一个任务级问题，而不是 122 个重复询问。

2.6 智能体角色

模型在流程中承担两类判断，均不产生金额：

  • 输入理解：判断邮件是否为询价单、抽取以散文书写的报价条款、标记可能读错的行；抽取结果逐字段回指原文并通过代码校验。
  • 对话助手：根据用户问题选择工具，读取当前任务的复核项、价格依据与条款，组织自然语言回答。

其余环节由确定性代码执行。模型未配置、超时或输出未通过校验时，系统回退确定性解析，并将实际执行的路径写入任务轨迹，界面同步显示。

层 选型 说明
语言 Python 3.11+，标准库优先 无需安装额外运行环境即可跑通完整流程
Web 服务 http.server 单进程、线程化请求，不依赖 Flask / FastAPI
前端 单文件 index.html + 原生 JavaScript 无构建步骤、无 CDN、无外部字体依赖

PDF 解析 自研 ingestion/pdf_text.py（纯标准库） 针对官方 PDF 的 Helvetica 字体与显式 Tm 定位，按坐标重建表格；不依赖 pypdf

依赖支持三种获取方式：本地 .deps/ 缓存、pip install -e ".[documents]"、系统已安装，均由 infrastructure/deps.py 统一处理。

4 创新点

  1. 四种载体、一条映射、证据落到单元格。 正文表格、制表符、xlsx 与 pdf 归一到同一套列名，因此只需维护一份 row → Line 映射。每行携带 evidence{file, container, sheet, row, column, raw}，第 ② 步显示原件位置与原始值，第 ③ 步显示邮件、附件、表、行、列与原值，可用原始文件逐格核对。

  2. 模型负责阅读，代码负责校验与计算。 模型只产出结构化结果，每个字段携带 value / raw / anchor / confidence。代码随后验证字段真实性：料号与数量必须能在其声称的行中原样找到（允许空格与连字符差异），数量必须可解析为正小数；置信度 ≥ 0.95 直接采用，0.70–0.95 采用并标记待确认，< 0.70 拒收。无法识别的列与行分别记入 unknown_columns 与 unparsed_rows，不静默丢弃。模型调用失败时回退确定性解析，并写入任务轨迹。

  3. 复核项按目标寻址，修改一个答案只重算一行。 复核项编号与目标绑定，作答后不重新编号；决策日志始终指向同一行或整案，revision 递增且其余行已确定的价格不受影响。

  4. 每单必出询价分析报告，包括无法报价的单。 转询价与不报价同样是工作成果。系统为每个任务生成 analysis-r<rev>.docx，包含逐行状态、原因、建议动作（向供应商询价、与客户确认计量单位、要求 FAA 8130-3 等）、定位信息与五条规则的核查统计。文档标题固定为「询价分析报告」。

  5. 合规门内置在定价路径中。 客户「询价产品要求」逐行参与定价：CERT REQUIRED 类要求只接受 EASA Form 1 / FAA 8130-3，PMA 与 CoC 判 cert_mismatch；库存记录不含证书时判 cert_unverified；SPECIAL REQUIREMENT 内容未说明则单列待确认项；单位按原文比较，不一致进入复核且不做换算；件号先精确匹配，再按大小写、空格、横杠归一或 MPN、手册件号匹配，非精确匹配必须人工确认；PMA 件即使价格最低，也需人工确认后采用。

  6. 空结果即结论。 无价格依据时返回空值、界面显示 —、仅提出一个任务级问题。系统不以估算价格填充缺失依据，这是报价结果可被信任的前提。

5 使用说明

5.1 访问方式

项目 说明
可运行智能体 https://rfq-agent-xk2m.onrender.com/
访问控制 公开访问，无需登录、邀请码或 API Key，无访问密码
运行环境 建议 Chrome / Edge 最新版本，1600 × 1000 以上分辨率

服务运行于 Render（新加坡区，Docker 部署），健康检查端点 GET /healthz。免费实例空闲 15 分钟后休眠，首次访问需等待 20–30 秒冷启动，页面不会报错。

5.2 操作步骤（案例 B，约 2 分钟）

  1. 打开链接，左侧「收件箱」中预置样例 B（Excel 附件，21 行）。
  2. 点击页面上方的「运行新任务」，系统完成解析与定价后停在「④ 人工预审」，状态显示「待确认 2」。
  3. 在「④ 人工预审」为两个待确认项各选择一项处理方式。
  4. 进入「⑥ 报价草案」，点击「生成报价草案」并下载 DOCX。

如需演示其他输入：左侧「演示素材」列出其余五封官方邮件，选择后会询问「打开已有任务」或「作为新任务运行」；也可将任意 .eml 拖入虚线区域，系统先给出导入预览，确认后才创建任务。

5.3 各步操作要点

步骤 操作 判定标准
① 输入采集 核对客户、询价号、载体与原件链接；展开「客户随附要求」阅读原文 询价号与原件一致，条款条数与邮件一致
② 结构提取 查看字段覆盖比例与带标记的行，必要时展开原始值与原件位置 料号、数量、单位覆盖率应为 100%；异常行有明确标记
③ 询价分析 逐行查看结果与定位，可横向滚动查看完整溯源信息 有依据的行给出单价与金额，无依据的行给出原因
④ 人工预审 对每个待预审项选择一个动作；无法判断时选择转人工询价 待预审项清零后才能继续
⑤ 分析报告 导出分析报告，核对统计数字与建议动作 报告包含逐行原因与定位
⑥ 报价草案 生成并下载报价草案，核对客户要求核对表 草案标注待复核，未计税费运费

5.4 官方素材处理结果

案例 载体 行数 有价格依据 待预审 解析结果与提示
A 正文 HTML 表格 122 109 22 项 9 组同询价号重复料号（共 9 行重复）、5 个料号跨询价号出现、EA 116 行 / IN 6 行、34 行缺优先级
B Excel 附件 21 19 2 项 1 个料号跨询价号出现（独立询价行，不按重复处理）、EA 20 行 / IN 1 行、6 行缺优先级
C PDF 附件 7 0 1 项（任务级） 件状与截止日期整列为空（记为该载体不含此列）、单位 Each 共 7 行、7 条客户要求
D 正文表格 122 0 1 项（任务级） EA 115 行 / FT 7 行、30 行缺优先级
E Excel 附件 21 0 1 项（任务级） EA 20 行 / FT 1 行、5 行缺优先级
F PDF 附件 7 0 1 项（任务级） 同案例 C：件状与截止日期整列为空、单位 Each 共 7 行、7 条客户要求

案例 A 的 22 项待预审分别来自件状不符、MOQ 超量、库存不足、PMA 选型、价格状态异常与 SPECIAL REQUIREMENT 六类规则，每一项独立作答，互不影响。

案例 C、D、E、F 的 0 行有价属于数据事实而非解析失败：价格资源表覆盖 PN-* 料号与标准件（NAS、MS、AN 等），而 C、F 的料号为 GSK-* / CPL-*，D、E 为 AP-*。系统的处理方式是说明原因、生成任务级问题并显示空小计。

5.5 命令行

python -m rfq_agent.web --port 8765                                    # 启动 Web 服务
python -m rfq_agent.cli case --case B                                  # 运行指定案例（A–F）
python -m rfq_agent.cli case --case B --resolve RI-0016=quote_with_moq --export
python -m rfq_agent.cli case --case B --autonomy auto_draft --export   # 按默认值解算全部复核项
python -m unittest discover -s tests -v                                # 运行全部用例
python -m rfq_agent.checkenv                                           # 环境自检

任务产物位于 runtime/<task_id>/：

文件 内容
draft-r<rev>.json 证据、决策日志与分析结构，可复算
analysis-r<rev>.docx 询价分析报告，每个任务均生成
quote-draft-r<rev>.docx 报价草案，仅可报价时生成
quote-r<rev>.docx 人工批准后的正式文件

5.6 部署与配置

docker build -t rfq-agent .
docker run -d -p 8000:8000 -e RFQ_DEMO_APPROVAL=1 rfq-agent

也可按仓库根目录的 render.yaml 在 Render 创建 Blueprint 实例。

环境变量 必填 作用
PORT 由平台注入 监听端口

7.2 人工确认边界

以下五项决策系统不代为执行，必须由具名人员确认：

  1. 接受替代件状（客户要求 FN，现货为 SV 或 OH）；
  2. 按供应商 MOQ 超额采购；
  3. 无价格依据时转人工询价或放弃报价；
  4. 对外发送前的最终价格与报价有效期；
  5. 采用 PMA 件（即使其为最低价）。
