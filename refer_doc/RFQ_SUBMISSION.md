# MatrixNEXT RFQ Agent

**航空备件询价处理智能体｜说明文档**

文档版本 1.0 ｜ 产品版本 0.1.0 ｜ 2026-11-10 ｜ 运行环境 Python 3.11+（实测 3.12.9）

## 摘要

MatrixNEXT RFQ Agent 是面向询价处理（RFQ）的智能体实现：接收客户发来的询价邮件（正文表格、Excel 附件或 PDF 表单），输出两份交付物——一份按客户模板填写的报价草案，一份逐行说明报价依据的询价分析报告。

航空备件是这套方案的落地场景：件号、件状、适航证书、交期与客户模板共同构成报价单的必要条件，任一缺失即被客户退回。方案主干（统一行项目、确定性定价、人工闸门、模板输出）与行业无关，行业差异集中在四处可替换的端点（见 2.7）。

系统将可验证的解析与计算交给确定性引擎，将不可让渡的商业判断交回具名的人。报价单上的每一个数字都能回溯到原始文件的单元格；没有价格依据的行不给估值，而是转人工询价并写明原因。

技术选型、性能数据与部署方式见附录 A。

## 1 问题定义

### 1.1 业务场景

询价是 B2B 交易中最常见的一类非结构化输入：买方以邮件提出需求，卖方在限定时间内回复一份可执行的价格与条件。这类流程的输入形态高度离散——正文表格、附件表格、PDF 表单、制表符文本都可能出现，同一买方前后两封邮件也可能换格式。

以航空备件为例，一份可交付的报价单需要同时满足：件号与数量准确、件状（FN / SV / OH）可接受、证书符合客户要求、交期与有效期齐全、金额与大写无误。这项工作包含四个环节：

1. **行项目提取**：从邮件正文或附件中取出料号、数量、单位、件状、截止日期。列名与格式不统一，同一批客户前后两封邮件可能分别是正文表格、Excel 附件与 PDF 表单。
2. **件状与合规判断**：客户要求全新件（FN）、可服务件（SV）或大修件（OH），供应商现货可能是另一种件状。是否接受替代件状，属于商业判断。
3. **价格依据检索**：内部物料成本表提供成本，价格资源表提供供应商报价。缺少依据时不能估算。
4. **按客户模板出单**：金额、大写、有效期与每行的件状、证书、交期必须齐全，缺项即被客户退回。

单封询价的行数从数行到上百行不等，本方案的验证数据集覆盖 6 封邮件、300 行、四种载体（见附录 A.3）。

### 1.2 关键痛点

| 环节 | 现状 | 后果 |
|---|---|---|
| 格式 | 输入载体不统一：正文 HTML 表格、正文制表符、Excel 附件、PDF 表单 | 每封都要人工重新对齐列名；百余行的单约需 1–2 小时；错行直接导致报错价 |
| 依据 | 价格来自内部参考表与供应商报价，覆盖不全 | 报价发出后无法回答"这行为什么这个价"，争议无法追溯 |
| 判断 | MOQ 超额采购、件状放宽、无价格依据被压缩成同一个"填个数字"的动作 | 三类性质不同的决策被掩盖，事后无法区分是计算错误还是商业选择 |
| 模板 | 客户模板的明细表行数固定，而实际询价行数不定 | 必须动态增行，手工处理容易破坏模板格式 |

### 1.3 设计目标

1. **载体无关**：新增载体不改变下游逻辑，四种输入产出同一套行项目与证据结构；
2. **可追溯**：每一行可回溯到「邮件 → 附件 → 表/页 → 行 → 列 → 原值」；
3. **依据缺失不估值**：没有价格依据时返回空值并说明原因，不产生估算价格；
4. **模板化输出**：输出为可交付的客户模板 DOCX，且明确标注为待复核草案；
5. **人机边界**：机器不代替客户做商业决定，人不需要重算数字；
6. **可迁移**：解析器、价格数据源、规则策略、输出模板均可替换，流程主干不变。

## 2 解决方案

### 2.1 方案概述

不同载体的输入归一到一套行项目结构，由确定性定价引擎完成候选装配与约束过滤，在需要商业判断处停下等待人工预审，最后填充客户模板并生成分析报告。

### 2.2 处理流程

```text
客户邮件（正文 HTML 表格 / 正文制表符 / .xlsx / .pdf）
   │  载体识别与解析；每行写入 evidence{file, container, sheet, row, column, raw}
   ▼
统一 RFQ 结构：单据字段 + 行项目 + 客户随附要求
   ▼
定价引擎：候选装配 → 硬约束过滤（件状 / 证书 / 单位 / 件号 / 时效）→ 加成与比价 → 复核项
   ▼
逐行核查
   ├─ 契约校验：每行有结果、来源可追、金额 = q2(单价 × 数量)
   ├─ 业务规则：件号匹配、证书、单位、件状、报价截止，逐行记录结论
   └─ 单据质量：重复料号、单位混用、缺字段、截止日期异常
   ▼
存在阻塞项时停在 awaiting_review；人工作答后 revision 递增并重算受影响的行
   ▼
询价分析报告 DOCX（每单必出） ＋ 报价草案 DOCX（可报价时）
   │  具名人工批准后，单事务写入历史报价表并生成正式文件
```

### 2.3 六步工作台

界面按处理流程分为六步，每一步的产物即为下一步的输入：

| 步骤 | 系统完成的工作 | 呈现内容 |
|---|---|---|
| ① 输入采集 | 锁定输入版本，识别载体、客户、询价号、评估日 | 原件链接、客户随附要求原文、模型理解结论、执行轨迹 |
| ② 结构提取 | 四种载体归一为行项目 | 每行料号、数量、单位、件状、截止日期、原始值、原件位置 |
| ③ 询价分析 | 查询数据快照、装配候选、执行硬约束 | 每行「有依据 / 待预审 / 阻断」、单价金额或原因、完整定位 |
| ④ 人工预审 | 生成阻塞项与可选动作 | 待预审卡片（问题、选项、依据、定位）与已通过记录 |
| ⑤ 分析报告 | 汇总处置结果与建议动作 | 已报价 / 待确认 / 转询价 / 不报价统计、逐行原因、规则核查结果 |
| ⑥ 报价草案 | 填充客户模板、计算金额大写、附加依据页 | 草案 DOCX 下载；启用演示策略时可执行批准入库 |

### 2.4 人机边界

| 系统负责 | 人负责 |
|---|---|
| 解析、归一、识别四种载体 | 决定无依据的行如何处理 |
| 按件状集合过滤候选、计算加成与比价 | 决定是否接受替代件状 |
| 标出重复料号、单位混用、日期异常 | 判断单据不一致是否影响本次报价 |
| 生成复核问题与明确选项 | 在给定选项中作出选择 |
| 填充模板、计算大写、编写依据页 | 对外发送前确认最终价格 |

### 2.5 关键设计决策

1. **价格只有一个来源。** 全部金额由确定性定价模块计算，模型仅参与理解与工具选择，不参与任何算术。对话助手获取的也是引擎结果，且载荷按页压缩，不传递完整行数据。
2. **复核项按目标寻址。** 复核项编号由目标推导（`RI-0016` 指第 16 行，`RI-TASK` 指整案），作答后不重新编号，决策日志始终指向同一对象；修改一个答案只重算受影响的行。
3. **空结果不可被填充。** 无价格依据时返回空值，小计显示 `—`；122 行均无依据的单据只生成一个任务级问题，而不是 122 个重复询问。

### 2.6 智能体角色

模型在流程中承担两类判断，均不产生金额：

- **输入理解**：判断邮件是否为询价单、抽取以散文书写的报价条款、标记可能读错的行；抽取结果逐字段回指原文并通过代码校验。
- **对话助手**：根据用户问题选择工具，读取当前任务的复核项、价格依据与条款，组织自然语言回答。

其余环节由确定性代码执行。模型未配置、超时或输出未通过校验时，系统回退确定性解析，并将实际执行的路径写入任务轨迹，界面同步显示。

### 2.7 方案的可迁移性

询价处理的主干与行业无关：**统一行项目 → 确定性规则与计算 → 人工闸门 → 模板化输出**。行业差异集中在四个端点，替换端点即可复用整条流程：

| 扩展点 | 当前实现 | 换场景需要做什么 |
|---|---|---|
| 输入解析 | 按载体分派：正文 HTML 表格、正文制表符、Excel 附件、PDF 表单，产出同一套行项目与证据结构 | 新增载体只需增加一个解析函数，下游定价、复核、导出不改动 |
| 价格数据源 | `QuoteProvider` 协议；当前实现查询本地参考表快照，无数据时返回空 | 对接 ERP、供应商目录或第三方价格服务，实现同一协议的 `evaluate()` |
| 规则与策略 | 策略字典（加成率、汇率、批准开关）＋ 合规与业务规则模块（件号、证书、单位、件状、时效） | 按行业替换规则表与证书集合，例如模具报价改为工艺工时，耗材报价改为包装规格 |
| 输出模板 | 客户 DOCX 模板 ＋ 自动追加的报价依据页 | 替换模板文件，金额大写与依据页由系统生成 |

数据模型、复核项机制、修订与审计记录、导出流程不需要按行业重写；这也是本项目以航空备件为场景、但可迁移到其他报价型询价业务的原因。

## 3 创新点

1. **载体无关的解析，证据落到单元格。**
   正文表格、制表符、xlsx 与 pdf 归一到同一套列名，因此只需维护一份 `row → Line` 映射，新增载体不影响下游。每行携带 `evidence{file, container, sheet, row, column, raw}`，第 ② 步显示原件位置与原始值，第 ③ 步显示邮件、附件、表、行、列与原值，可用原始文件逐格核对。

2. **模型负责阅读，代码负责校验与计算。**
   模型只产出结构化结果，每个字段携带 `value / raw / anchor / confidence`。代码随后验证字段真实性：料号与数量必须能在其声称的行中原样找到（允许空格与连字符差异），数量必须可解析为正小数；置信度 ≥ 0.95 直接采用，0.70–0.95 采用并标记待确认，< 0.70 拒收。无法识别的列与行分别记入 `unknown_columns` 与 `unparsed_rows`，不静默丢弃。模型调用失败时回退确定性解析，并写入任务轨迹。

3. **复核项按目标寻址，修改一个答案只重算一行。**
   复核项编号与目标绑定，作答后不重新编号；决策日志始终指向同一行或整案，revision 递增且其余行已确定的价格不受影响。

4. **每单必出询价分析报告，包括无法报价的单。**
   转询价与不报价同样是工作成果。系统为每个任务生成 `analysis-r<rev>.docx`，包含逐行状态、原因、建议动作（向供应商询价、与客户确认计量单位、要求 FAA 8130-3 等）、定位信息与五条规则的核查统计。文档标题固定为「询价分析报告」。

5. **合规门内置在定价路径中。**
   客户「询价产品要求」逐行参与定价：`CERT REQUIRED` 类要求只接受 EASA Form 1 / FAA 8130-3，PMA 与 CoC 判 `cert_mismatch`；库存记录不含证书时判 `cert_unverified`；`SPECIAL REQUIREMENT` 内容未说明则单列待确认项；单位按原文比较，不一致进入复核且不做换算；件号先精确匹配，再按大小写、空格、横杠归一或 MPN、手册件号匹配，非精确匹配必须人工确认；PMA 件即使价格最低，也需人工确认后采用。

6. **空结果即结论。**
   无价格依据时返回空值、界面显示 `—`、仅提出一个任务级问题。系统不以估算价格填充缺失依据，这是报价结果可被信任的前提。

## 4 使用说明

### 4.1 访问方式

| 项目 | 说明 |
|---|---|
| 可运行智能体 | https://rfq-agent-xk2m.onrender.com/ |
| 访问控制 | 公开访问，无需登录、邀请码或 API Key，无访问密码 |
| 运行环境 | 建议 Chrome / Edge 最新版本，1600 × 1000 以上分辨率 |

服务运行于 Render（新加坡区，Docker 部署），健康检查端点 `GET /healthz`。免费实例空闲 15 分钟后休眠，首次访问需等待 20–30 秒冷启动，页面不会报错。

### 4.2 操作步骤（约 2 分钟）

1. 打开链接，左侧「收件箱」已预置一个 21 行的 Excel 附件样本。
2. 点击页面上方的「运行新任务」，系统完成解析与定价后停在「④ 人工预审」，状态显示「待确认 2」。
3. 在「④ 人工预审」为两个待确认项各选择一项处理方式。
4. 进入「⑥ 报价草案」，点击「生成报价草案」并下载 DOCX。

如需查看其他载体：左侧素材库列出其余样本，选择后会询问「打开已有任务」或「作为新任务运行」；也可将任意 `.eml` 拖入虚线区域，系统先给出导入预览，确认后才创建任务。

### 4.3 各步操作要点

| 步骤 | 操作 | 判定标准 |
|---|---|---|
| ① 输入采集 | 核对客户、询价号、载体与原件链接；展开「客户随附要求」阅读原文 | 询价号与原件一致，条款条数与邮件一致 |
| ② 结构提取 | 查看字段覆盖比例与带标记的行，必要时展开原始值与原件位置 | 料号、数量、单位覆盖率应为 100%；异常行有明确标记 |
| ③ 询价分析 | 逐行查看结果与定位，可横向滚动查看完整溯源信息 | 有依据的行给出单价与金额，无依据的行给出原因 |
| ④ 人工预审 | 对每个待预审项选择一个动作；无法判断时选择转人工询价 | 待预审项清零后才能继续 |
| ⑤ 分析报告 | 导出分析报告，核对统计数字与建议动作 | 报告包含逐行原因与定位 |
| ⑥ 报价草案 | 生成并下载报价草案，核对客户要求核对表 | 草案标注待复核，未计税费运费 |

### 4.4 验证样本与结果

验证数据集覆盖四种载体与两类价格覆盖情况（有依据 / 无依据）。两份 PDF 样本特征一致，合并为一行展示：

| 样本 | 载体 | 行数 | 有价格依据 | 待预审 | 观察到的数据特征 |
|---|---|---|---|---|---|
| 1 | 正文 HTML 表格 | 122 | 109 | 22 项 | 9 组同询价号重复料号（共 9 行重复）、5 个料号跨询价号出现、EA 116 行 / IN 6 行、34 行缺优先级 |
| 2 | 正文表格（制表符） | 122 | 0 | 1 项（任务级） | EA 115 行 / FT 7 行、30 行缺优先级；料号前缀不在参考表覆盖范围 |
| 3 | Excel 附件 | 21 | 19 | 2 项 | 1 个料号跨询价号出现（独立询价行，不按重复处理）、EA 20 行 / IN 1 行、6 行缺优先级 |
| 4 | Excel 附件 | 21 | 0 | 1 项（任务级） | EA 20 行 / FT 1 行、5 行缺优先级；料号前缀不在参考表覆盖范围 |
| 5 | PDF 表单 | 7 | 0 | 1 项（任务级） | 件状与截止日期整列为空（记为该载体不含此列）、单位 `Each`、7 条客户要求；料号不在覆盖范围 |

样本 1 的 22 项待预审分别来自件状不符、MOQ 超量、库存不足、PMA 选型、价格状态异常与 `SPECIAL REQUIREMENT` 六类规则，每一项独立作答，互不影响——这验证的是多规则并行时的闸门粒度，而不是某个特定样本。

样本 2、4、5 的 0 行有价属于数据覆盖事实而非解析失败：价格资源表覆盖 `PN-*` 料号与标准件（`NAS`、`MS`、`AN` 等），而这些样本的料号前缀为 `AP-*`、`GSK-*`、`CPL-*`。系统的处理方式是说明原因、生成一个任务级问题并显示空小计，而不是逐行弹出上百个对话框。

## 5 数据合规说明

### 5.1 数据来源与范围

- 仅使用赛事提供的演示与脱敏数据：`data/询价信息素材/`（6 封 `.eml`、2 个 PDF、2 个 xlsx）、`价格资源表_演示数据.xlsx`（342 行）、`内部物料成本表_演示数据.xlsx`（163 行）、`报价单样例.docx`。
- 客户名称形如「客户A」「客户B」「Buyer C」，邮件域名为 `customer.test` / `supplier.test`；数据中不含真实客户、供应商、价格或个人信息。
- 不使用来源不明的第三方数据，不抓取公开网页，不做竞品数据采集。

### 5.2 数据流向

| 数据 | 存放位置 | 是否发送至外部服务 |
|---|---|---|
| 询价邮件与附件 | `runtime/uploads/`、`runtime/<task_id>/`、SQLite | 仅可读文本块发送至模型接口用于理解（见 5.4） |
| 价格资源表、内部成本表 | `runtime/rfq.db`（只读快照，按文件哈希增量更新） | 否，价格计算全部在本地完成 |
| 任务、决策日志、历史报价 | `runtime/`、SQLite | 否；对话助手仅接收任务摘要 |
| 导出文档 | `runtime/<task_id>/` | 否，由用户自行下载 |

### 5.3 用户上传文件

- 仅接受 `.eml` 格式。预览阶段文件存放在 `runtime/uploads/.pending/`，不进入素材扫描，也不创建任务；未确认的预览文件在服务重启时清理。
- 用户确认导入后，文件存放于 `runtime/uploads/`，解析结果写入本机 SQLite。
- 文件不转发第三方、不进入共享库、不做跨实例同步或云端备份；删除 `runtime/uploads/` 与对应任务目录即可清除。

### 5.4 模型调用

- **用途**：判断邮件是否为询价单、抽取正文报价条款、标记可疑行；对话助手用于工具选择。
- **发送范围**：该封邮件的可读内容块（正文文本、表格单元格、PDF 文本行），单块不超过 400 行，单次请求分页 50 行。
- **不发送**：价格资源表、内部物料成本表、历史报价、其他任务数据、任何凭据或个人信息。
- **服务方**：赛事提供的 Genesis 网关（OpenAI 兼容接口）。数据仅用于本次推理，不用于模型训练；请求体不在服务端留档，任务记录中只保存所用模型名称与解析结论。
- 未配置访问令牌时该层整体禁用，产品功能不受影响。

### 5.5 凭据与日志

- 访问令牌仅存在于服务端环境变量；`.env` 已纳入 `.gitignore`，仓库不含令牌；前端页面、导出文档与运行日志均不展示。
- 页面仅显示文件名，不显示服务器绝对路径；访问日志只记录请求路径与状态码，不记录请求体。
- 演示实例不设账号体系，任何持链接者可试用，但数据全部为演示数据，不构成真实信息泄露。

### 5.6 输出定位与责任边界

- 报价草案备注声明「本报价为待复核草案，须经人工确认后方可对外发送」，并注明税费、运费、包装费口径与库存可售状态待企业确认、演示价格基准日与策略版本。
- 询价分析报告首页声明「本文件是询价分析记录，不构成对外报价，不得对外发送」。
- 系统不代发邮件、不自动下单、不对外承诺价格。
- 最终价格、件状放宽、超额采购、无依据转运维、PMA 件采用，五项决策必须由具名人员确认（见 6.2）。

### 5.7 保留期限与销毁

- 演示数据与任务记录仅保留在服务实例本地，评审期内有效；评审结束后可整体销毁实例或删除 `runtime/` 目录。
- 数据不向任何第三方归档、出售或交换。

### 5.8 第三方组件

- `openpyxl`（MIT）、`python-docx`（MIT）、`lxml`（BSD）：均在本机运行，不联网。
- 不含统计、埋点、广告或分析 SDK；系统唯一的出站请求为配置的模型接口。

## 6 已知限制与人工确认边界

### 6.1 已知限制

| 限制 | 说明 | 影响与应对 |
|---|---|---|
| 实例休眠与临时磁盘 | Render 免费实例空闲 15 分钟休眠；磁盘为临时存储，重启后进行中的任务清空 | 首次访问需 20–30 秒冷启动；重启后重新运行任务即可，收件箱回到初始状态 |
| PDF 解析范围 | 仅支持样本数据集所用的 Helvetica 字体、显式 `Tm` 定位、无压缩流表单 | 其他构造的 PDF 明确报错，不做猜测；通用场景需引入 pypdf 或版式识别 |
| 价格覆盖 | 342 行价格表仅覆盖 `PN-*` 与标准件 | 样本 2、4、5 为 0 行有价，属数据事实 |
| 条款回灌 | 已核对草案是否满足客户要求，未将条款回灌定价策略（例如"有效期 30 天"不改变报价有效期计算） | 需人工按条款确认 |
| 并发能力 | 单进程 SQLite，写入串行 | 适用于演示与单用户操作，不适合并发压测 |
| 出口管制判定 | 仅提示，不自动判定 | 需人工确认 |
| 模型依赖 | 单次理解耗时 5–13 s，网关负载高时可能超时 | 模型为可选增强层，主流程不依赖；超时自动回退确定性解析 |
| 上传格式 | 仅支持 `.eml` | 其他格式需先转换，或使用内置演示素材 |

### 6.2 人工确认边界

以下五项决策系统不代为执行，必须由具名人员确认：

1. 接受替代件状（客户要求 FN，现货为 SV 或 OH）；
2. 按供应商 MOQ 超额采购；
3. 无价格依据时转人工询价或放弃报价；
4. 对外发送前的最终价格与报价有效期；
5. 采用 PMA 件（即使其为最低价）。

## 附录 A 技术实现

### A.1 技术栈与分层

系统按职责分层，业务逻辑不依赖任何 Web 框架：

| 层 | 选型 | 说明 |
|---|---|---|
| 传输层（适配器） | `http.server` | 单进程、线程化请求；只负责路由、静态资源与 JSON 序列化，业务对象不感知 HTTP |
| 应用层 | `RFQService` | 任务编排、修订管理、状态机与审计；不引入框架依赖 |
| 领域层 | 定价、单据质量、业务规则、合规、条款核对 | 纯函数与策略对象，可独立单测，不触达 IO |
| 适配层 | 载体解析（HTML / 制表符 / xlsx / 自研 PDF）、SQLite 价格快照、DOCX 导出 | 通过 `ports` 协议注入，可替换 |
| 模型层 | Genesis（OpenAI 兼容），`deepseek-v4.1-flash` | 负责输入理解与工具选择；未配置时整体禁用 |
| 前端 | 单文件 `index.html` ＋ 原生 JavaScript | 无构建步骤、无 CDN、无外链字体 |
| 存储 | SQLite（`runtime/rfq.db`） | 价格与成本表按源文件哈希只读一次，之后按料号索引查询 |
| 表格与文档 | openpyxl、python-docx | 读取附件与参考表；在客户模板上填充并保留样式 |
| 测试 | `unittest` | 173 个用例，覆盖解析、定价、复核、导出与接口 |
| 部署 | Dockerfile ＋ Render Blueprint ＋ `GET /healthz` | 识别 `PORT` / `RFQ_HOST`，SIGTERM 正常退出 |

依赖支持三种获取方式：本地 `.deps/` 缓存、`pip install -e ".[documents]"`、系统已安装，均由 `infrastructure/deps.py` 统一处理。

### A.2 选型取舍

| 决策 | 取舍 | 代价与迁移路径 |
|---|---|---|
| 传输层使用标准库而非 Web 框架 | 零框架依赖、单文件可审、容器直接启动，无需安装 | 缺少中间件生态（鉴权、限流、OpenAPI 文档）；应用层无框架依赖，接入 ASGI（FastAPI / Starlette）只需新增一个适配入口，业务代码不动 |
| 单进程 SQLite | 免运维、事务边界清晰 | 写入串行，不适合并发压测；替换为 Postgres 时只需替换 `infrastructure/db` |
| 自研 PDF 解析（标准库） | 零依赖、对不支持的构造明确报错 | 仅覆盖特定 PDF 构造；通用化时替换为 pypdf 或版式识别，接口不变 |
| 模型只做理解与工具选择 | 价格不可能被编造，结果可复算 | 无法处理完全非结构化的报价依据；由数据适配器承接新来源 |
| 单文件前端 | 无构建链、可直接读源码 | 缺少组件化与状态管理；页面规模增长后需拆分构建 |

### A.3 数据规模与性能

| 项目 | 数值 |
|---|---|
| 验证数据集 | 6 封询价邮件，300 行，四种载体 |

| 邮件解析（Excel 附件） | 21 行 | 0.02 s |

### A.4 命令行与产物

```powershell
python -m rfq_agent.web --port 8765                                    # 启动 Web 服务
python -m rfq_agent.cli case --case B                                  # 运行指定样本（A–F）
python -m rfq_agent.cli case --case B --resolve RI-0016=quote_with_moq --export
python -m rfq_agent.cli case --case B --autonomy auto_draft --export   # 按默认值解算全部复核项
python -m unittest discover -s tests -v                                # 运行全部用例
python -m rfq_agent.checkenv                                           # 环境自检
```

任务产物位于 `runtime/<task_id>/`：

| 文件 | 内容 |
|---|---|
| `draft-r<rev>.json` | 证据、决策日志与分析结构，可复算 |
| `analysis-r<rev>.docx` | 询价分析报告，每个任务均生成 |
| `quote-draft-r<rev>.docx` | 报价草案，仅可报价时生成 |
| `quote-r<rev>.docx` | 人工批准后的正式文件 |

### A.5 部署与配置

```powershell
docker build -t rfq-agent .
docker run -d -p 8000:8000 -e RFQ_DEMO_APPROVAL=1 rfq-agent
```

也可按仓库根目录的 `render.yaml` 在 Render 创建 Blueprint 实例。

| 环境变量 | 必填 | 作用 |
|---|---|---|
| `PORT` | 由平台注入 | 监听端口 |
| `RFQ_HOST` | 建议 `0.0.0.0` | 绑定地址，默认仅回环 |
| `GENESIS_BASE_URL` / `GENESIS_MODEL` / `GENESIS_ACCESS_TOKEN` | 可选 | 模型理解与对话层；未配置时降级为确定性解析 |
| `RFQ_DEMO_APPROVAL` | 可选（`1`） | 启用「批准入库」演示策略，产物标注「演示批准」 |

存储为单进程 SQLite，不可启用多 worker；服务无状态依赖，只需 `data/` 目录（随仓库发布）与可写的 `runtime/`。

## 附录 B 术语表

| 术语 | 含义 |
|---|---|
| RFQ | Request for Quotation，客户发起的询价请求 |
| 件状（Condition） | 航空备件的物理与维修状态：FN 全新件、SV 可服务件、OH 大修件 |
| MOQ | Minimum Order Quantity，供应商最小起订量 |
| PMA | Parts Manufacturer Approval，零部件制造人批准件，非适航放行证书 |
| CoC | Certificate of Conformance，合格证，不等同于适航放行证书 |
| EASA Form 1 / FAA 8130-3 | 欧洲 / 美国航空当局的适航放行证书，用于证明件的适航状态 |
| UOM | Unit of Measure，计量单位（EA、IN、FT、Each 等） |
| 转人工询价 | 无可用价格依据时，将行项目转交人工向供应商询价，不给出估算价格 |
