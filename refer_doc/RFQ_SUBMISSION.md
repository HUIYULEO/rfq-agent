# 说明文档（§13.3 提交用）

本文件对应赛事提交要求的三份材料之一。演示视频脚本见 [RFQ_DEMO_SCRIPT.md](RFQ_DEMO_SCRIPT.md)，
工程细节见 [../README.md](../README.md)，方案设计见 [RFQ_SOLUTION_DESIGN.md](RFQ_SOLUTION_DESIGN.md)。

## 1. 问题定义

航空备件供应商收到客户询价（RFQ），要在一两天内回一张报价单。真实工作包含四步：

1. **把行项目抠出来**。同一批客户，附件形态不统一：正文 HTML 表格、正文制表符、Excel 附件、PDF 表单。
   列名不统一（Part Number / 料号、Qty / 数量），优先级、交期、件状条件有的在表里，有的只在正文里。
2. **判断件状能不能接受**。客户写 FN（全新件）、SV（可服务件）、OH（大修件）等，
   供应商现货可能是另一种件状。这是商业判断，不是查表。
3. **找价格依据**。内部成本表给成本，价格资源表给供应商报价。缺一边就不能凭感觉加价；
   两边都没有就必须转人工询价。
4. **按客户模板出单**。金额、大写、有效期、每行的件状/证书/交期，缺一项客户就退回。

痛点不在"打字慢"，在三处不可控：

- **格式不可控**：每封邮件都要人眼重新对齐列名，一次 122 行。
- **依据不可控**：报价单发出去，三天后客户问"这行为什么这个价"，答不上来。
- **判断混在计算里**：MOQ 超采、件状放宽、无价格依据，本来是三个不同性质的决策，
  在 Excel 里被压成同一个"填个数字"的动作。

## 2. 解决方案

### 2.1 一句话

**四种输入 → 一份统一的行项目 → 一个确定性定价引擎 → 停在人该决定的地方 → 客户模板草案。**

### 2.2 数据流

```text
.eml（正文 HTML / 正文制表符 / .xlsx / .pdf）
      ↓  ingest.py      四种载体归一到同一套列名，每行带 evidence{file, container, row}
RFQ：单据级字段 + 行项目 + 客户随附要求
      ↓  quality.py     单据本身的不一致（重复料号、单位混用、缺字段、日期异常）
      ↓  pricing.py     候选装配 → 硬约束过滤 → 加成/比价 → 复核项
结果：每行 eligible（内部/供应商/转人工）+ 依据 + 决策理由
      ↓  人工闸门        有阻塞项就停在 awaiting_review，答完才继续，revision 递增
      ↓  export_docx.py  官方模板填充 + 依据摘要页 + 金额大写
quote-draft-r<rev>.docx（草案，不是可直发的正式报价）
```

### 2.3 人机边界

| 机器做 | 人做 |
|---|---|
| 解析、归一、去空格、识别四种载体 | 决定没有依据的行怎么办 |
| 按件状集合过滤候选、算加成、比价 | 决定要不要放宽件状 |
| 标出重复料号、单位混用、缺优先级 | 判断这些不一致是否影响本次报价 |
| 生成复核问题与选项 | 从给定选项里选一个 |
| 填模板、算大写、写依据页 | 对外发送前复核 |

这条边界是产品的一部分：**机器不替客户做商业决定，人不需要重算数字**。

### 2.4 三个设计取舍

1. **价格只有一个来源**。所有数字来自 `pricing.py` 的纯函数；模型只能调工具，不能算数。
   工具返回的也是引擎结果，模型的载荷被压缩（不塞 122 行原始数据）。
2. **复核项按目标寻址**。`RI-0016` 指第 16 行，`RI-TASK` 指整案。答完不重新编号——
   否则决策日志会指向错的对象。改一个答案只重算受影响的行，不影响其他行已定的价。
3. **没有依据就说没有**。122 行的单如果参考表里没有这些料号，系统只产生**一个**任务级问题
   （"整体转人工询价"），而不是刷 122 个对话框；小计显示 `—` 而不是 `¥0.00`。

## 3. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.11+，标准库优先 | 评委环境零安装即可跑；无框架依赖 |
| Web 服务 | `http.server` | 单文件路由，无 Flask/FastAPI 依赖 |
| 前端 | 单页 HTML + 原生 JS | 无构建步骤，`index.html` 直接可读可改 |
| 存储 | SQLite（`sqlite3`） | 价格/成本表只读一次，之后按料号索引查询 |
| Excel | openpyxl | 读素材、写能力都够 |
| Word | python-docx | 直接在官方模板上填，保留格式 |
| PDF | 自研 `pdf_text.py`（标准库） | 官方 PDF 是 Helvetica + 显式 `Tm`，无需 pypdf |
| 模型层 | OpenAI 兼容接口（Genesis `deepseek-v4.1-flash`） | 只做工具选择；未配置时按钮流程照常可用 |
| 测试 | `unittest`，61 个用例 | 无 pytest 依赖 |

依赖全部可缺省：`.deps/` 本地缓存、`pip install -e ".[documents]"`、或系统已装，三条路都走同一个 `deps.py`。

### 3.1 数据规模（实测）

| 项 | 数值 |
|---|---|
| 官方邮件 | 6 封，300 行 |
| 价格资源表 | 342 行（其中 276 行是 `PN-*`） |
| 内部物料成本表 | 163 行 |
| 有价格依据 | 128 行（A 109 / B 19；C/D/E/F 为 0） |
| 解析耗时 | A 122 行 0.05 s，B 21 行 0.02 s |
| 定价耗时 | A 0.03 s，B 0.005 s |
| 点击到待确认 | 0.4 s |
| 冷启动读表 | 约 3 s（仅首次，之后走 `runtime/rfq.db`） |

## 4. 创新点

1. **载体无关的解析，证据到单元格**。四种载体走同一条 `row → Line` 映射，
   每行带 `{file, container, row}`。页面上点开任意一行，能看到"这行来自哪个文件的第几行"——
   评委可以拿原始 Excel 对。
2. **确定性定价 + 人工闸门的组合**。不是"AI 报价"，是"AI 把该做的做完、把不该做的留给人的产品化"。
   复核项带选项、带目标、带重算范围；答完只重算受影响的行。
3. **单据质量检查**。除了报价，还检查单据本身：重复料号（A 有 10 个料号 14 行重复）、
   单位混用（EA/IN、EA/FT）、部分行缺优先级、交期早于评估日。整列全空的按"载体不含此列"记录，
   不当缺陷。这些只提示，不改价。
4. **条款也进结构化结果**。英文邮件的编号要求（3 条）和 PDF 表单上的响应指示（4 条）
   原文照录并标注出处，一并写进草案第二页——评委打开 DOCX 就能看到依据。
5. **不可欺骗的空结果**。没有价格依据时返回 `null`、界面显示 `—`、只问一个任务级问题。
   这比"给个看起来合理的数字"难做，但它是能不能被信任的分界线。

## 5. 使用说明

### 5.1 访问方式

当前版本是**本地可运行实例**，双击 `start.cmd` 即在 `http://127.0.0.1:8765/` 启动并自动打开浏览器，
不需要登录、不需要配置 API Key、不需要命令行。

> **在线链接状态：待部署。** 赛事要求评委通过链接直接访问，这一步需要在 MOI（或任意云主机）
> 上托管本服务。部署步骤见 5.4；在此之前请以本地实例 + 演示视频作为验证依据。
> 本文件不假装已有公网地址。

### 5.2 三步操作

1. **选单**：左侧「待处理」预置了样例 B（Excel 附件，21 行）。
2. **开始处理**：点中部「开始处理」，它会解析、定价，然后停在「需要你决定」。
3. **回答问题 → 导出**：每个问题给 2–3 个明确选项；答完出现「导出草案」，下载 DOCX。

顶部的「可导入素材」是其余五封邮件，点「导入」才进来；也可以把自己的 `.eml` 拖进虚线框。
左下角「重置演示数据」把收件箱恢复到只有样例 B 的状态（连续演示用）。

### 5.3 命令行（等价入口，便于复现）

```powershell
python -m rfq_agent.cli case --case B                                   # A..F
python -m rfq_agent.cli case --case B --resolve RI-0016=quote_with_moq --export
python -m rfq_agent.cli case --case B --autonomy auto_draft --export     # 全按默认值解算
python -m unittest discover -s tests -v                                  # 61 个用例
python -m rfq_agent.checkenv                                             # 环境自检
```

产物：`runtime/<task_id>/draft-r<rev>.json`（证据 + 决策日志）、`quote-draft-r<rev>.docx`。

### 5.4 部署到公网（待执行）

```powershell
# 任意一台有 Python 3.11+ 的机器
git clone <repo> && cd rfq-agent
pip install -e ".[documents]"
python -m rfq_agent.web --port 8765          # 或：python -m rfq_agent.web --host 0.0.0.0 --port 8765
```

前面加 Nginx/Caddy 反代到 443 即可。服务无状态依赖，只需要 `data/` 与可写的 `runtime/`。
若部署到 MOI：把 `rfq_agent` 作为包导入，用 MOI 的入口挂载 `web.py` 的 `Handler`，
或直接把 `python -m rfq_agent.web` 作为容器命令。

## 6. 数据合规说明

- **数据来源**：仅使用赛事提供的演示/脱敏数据（`data/询价信息素材/`、`data/价格资源表_演示数据.xlsx`、
  `data/内部物料成本表_演示数据.xlsx`、`data/报价单样例.docx`）。不含真实客户、供应商、
  价格或个人信息；客户名称形如「客户A」「Buyer C」，域名为 `.test`。
- **上传文件**：用户拖入的 `.eml` 只写入本机 `runtime/uploads/`，解析结果写入本机 `runtime/rfq.db`。
  不上传到任何第三方；不发送给模型——只有任务摘要（行数、金额、复核项、条款）会进入对话上下文。
- **模型调用**：仅通过 Genesis 接口做工具选择与措辞组织，不用于训练，不提交原始表格。
  未配置 token 时该层整体禁用，功能不受影响。
- **凭据**：`.env` 已在 `.gitignore` 中，仓库不含 token；界面与文档不展示任何密钥。
  若曾把 token 写进任何提交历史，应在赛后立即轮换。
- **输出定位**：所有 DOCX 首页与备注均标注「待复核草案」，声明税费运费未计入、不预留库存。
  **最终价格与对外承诺必须由人确认**，系统不代发邮件、不自动下单。

## 7. 已知限制与人工确认边界

| 限制 | 现状 | 影响 |
|---|---|---|
| 公网在线链接 | 未部署（见 5.4） | 评委目前需本地运行或用演示视频 |
| PDF 解析 | 只支持官方那种"显式 `Tm` + Helvetica"的表单；其他 PDF 会明确报错 | 通用 PDF 需换 pypdf/excel 转换 |
| 价格覆盖 | 342 行价格表只覆盖 `PN-*` 与标准件；`GSK-*`/`AP-*`/`CPL-*` 无依据 | C/D/E/F 0 行有价，这是数据事实，不是解析失败 |
| 条款 | 原文照录，未回灌到定价策略（如"有效期 30 天"未改变报价有效期计算） | 需人工按条款填 |
| 多用户 | 单进程存储，串行写；对话已移出存储锁 | 不适合并发演示 |
| 出口管制/合规 | 只做提示，不自动判定 | 需人工确认 |
| 模型 | `deepseek-v4.1-flash` 单轮 8–13 s；`qwen3.8-max` 曾超时 | 对话层是可选增强 |

**人工确认边界（不可让渡）**：件状放宽、超额采购、无依据转运维、对外发送前的最终价格。
