# 模型理解状态与降级展示

本次从 `main` 的 `26cc819` 开发，落实 LLM 架构草案中可独立验收的第一项：如实记录模型理解状态。没有合并或替代 PR #6 的架构草案，也不表示其第 1 阶段全部完成。

## 行为

- 规则解析 + 模型审查成功、模型抽取并通过现有校验：记录 `model_ran=true`、`degraded=false`。
- 未配置、超时、连接失败、接口报错、无效 JSON/响应、理解结果不可用：规则解析可用时记录 `model_ran=false`、`degraded=true` 和稳定的 `fallback_code`；展示中文原因，不将上游异常原文写入新的降级报告。
- 模型和规则都无法读取：继续报错，不伪造空 RFQ 或成功记录。
- 旧任务有 `source` 时按已记录来源展示；无来源记录的任务（包括没有记录输入理解的 CLI 任务）显示“模型理解状态未记录”，不推断成功或未配置。

`model_ran` 的含义是**本次获得了可用的模型理解结果**，不是“曾发起 HTTP 请求”。超时或无效响应均为 false；此字段不计费，也不计调用次数。

`domain/input_status.py` 统一生成面向用户的状态。输入采集、询价分析、分页分析报告、执行轨迹、导出的 JSON 分析结构与 DOCX 使用同一口径。规则定价、人工复核、商业批准门保持不变。旧的已导出文件不会被读取操作自动重写；重新导出时才采用新展示。

## 验证

- 新增回归涵盖缺配置跳过模型、超时/网络/接口/JSON 错误分类、双路径失败、旧记录兼容、状态持久化与报告导出。
- 六个真实官方案例使用现有素材，模型审查替换为固定测试响应，验证开/关两条路径的完整定价结果 JSON 一致。不以此声称真实模型接口已验证。
- 无头浏览器检查未配置、超时、成功、无记录四种状态在输入采集、询价分析、分析报告中的展示，以及降级执行轨迹。
