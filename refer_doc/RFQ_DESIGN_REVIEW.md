## 3. 阻断级问题（建议 P0 之前改）

### 3.1 【最严重】V0 选定 Buyer C，而 C 的价格覆盖率是 0/7

- **证据**：C 的 7 个行项目料号为 `GSK-001`…`GSK-007`，在两张参考表 163 个料号中均不存在（供应商表、内部表都不含任何 `GSK-` 前缀）。F 的 `CPL-` 同理为 0。
- **影响**：方案 §4.1 把 V0 定义为"解析邮件及 PDF → 得到 RFQ-0930 和 7 个行项目 → **匹配价格依据** → 形成报价建议 → 生成报价草案"，而计划 §4 的 P0 退出门是"**确认 C 的匹配覆盖率**"。这两条必然失败：C 只能产出 7 行 null 价格。V0 这个"垂直切片"恰好切在了唯一无法验证报价链路的案例上。
- **建议**：
  1. V0 拆两段：**V0a = C**（解析、英文条款、证据、7 行、全行 needs_review，报价列全空——这本身是"系统不编价"的好演示）；**V0b = B**（解析→候选→过滤→计算→DOCX，唯一能在 21 行上演示"每个数字有出处"的案例）。
  2. P0 退出门改为"**按案例**核定覆盖率"，并把 3.1 的表冻结进 `docs/data_dictionary.md`，而不是只留 DATE_EVIDENCE 里"AP-2001 没有精确匹配"一句。
  3. 把"4 个案例零价格覆盖"升级为**已知素材事实**写进事实基线，避免后续被当成 bug 反复排查。

### 3.2 "六案例 MVP 完整闭环"的表述与数据不符

- **证据**：同 3.1。只有 A、B 两个案例能走到报价；C/D/E/F 四例无论解析多准，都不可能产生报价数字。
- **影响**：M3、P1 退出条件、验收口径第 1 条（"六案例全部有终态与下载草案"）在字面上可满足，但"六案例完整闭环"会让人（尤其是评委和未来的自己）误读为"六例都有报价"。到 P3 才发现，会引发一轮不必要的返工和一次自我怀疑。
- **建议**：把闭环定义成两段并写进事实基线：**解析-校验闭环 6/6；候选-报价闭环 2/6**；其余 4 例的期望结果明确为"全行 needs_review + 原因=无价格依据 + 建议人工询价"。这反而是差异化卖点（可解释地拒绝报价）。

### 3.3 "正文型"是两种编码，不是一个模式

- **证据**：A 的 `text/plain` 每行是拼接串，无分隔符：`9000000001PN-0001WASHER 垫片8EAPN-0001FNPN-0001一般备件2026-09-15 10:00:00`；D 的 `text/plain` 是标准 TAB 分隔。两者 HTML 都是 1 个 `<table>`、123 个 `<tr>`、1464 个 `<td>`。
- **影响**：
  - 文档把"正文型"当一种模式、两套样例互为回归，实际 A 只能靠正则切分，鲁棒性远低于 D；如果按 text/plain 实现，A 会在 P3 爆掉。
  - INGEST-003 只写"解析正文内嵌表格"，没指定走 HTML 还是 plain text，这是实现阶段最容易分叉的一处。
- **建议**：INGEST-003 明确"**优先解析 `text/html` 的 table；`text/plain` 仅作降级**"，并标注 A 为难例、D 为易例；A 排到 P3，不进 P1。

### 3.4 价格状态与有效期至自相矛盾（27/342），规则未定义优先级

- **证据**：27 条 `价格状态 = 已过期` 的行，`有效期至` 全部 ≥ 2026-09-13，即业务日期（09-07 / 09-08）当天**并未到期**；315 条"有效"行的有效期同样全部未过期。也就是说只有状态字段能区分，日期字段完全区分不了。
- **影响**：RULE-001 只写"过滤过期或无效价格"，未定义两个字段冲突时谁优先。两种实现（以 status 为准 / 以日期为准）会得到 27 行差异，直接落在"报价数字可复现"这条验收上。
- **建议**：
  1. 明确一条：`status == 有效 AND valid_until >= evaluation_date` 双条件（此口径下 27 条判 rejected，理由 `status_invalid`，并保留两条原始证据）。
  2. 附注一个易被漏掉的事实：**素材中没有任何价格在 09-07/09-08 当天过期**（最近的是 2026-09-13），所以验收第 6 条的"过期当天"边界**必须用合成 fixture**，不能拿官方数据充数。

## 4. 需要在 P1 前补齐的契约

### 4.1 DOCX 模板与决策模型的字段映射缺失

模板明细行是 `序号 | 产品名称 | 规格 | 型号 | 数量 | 单位 | 金额 | 销售总价（元） | 备注`，全篇**没有"单价"列，也没有税率、币种、汇率、付款方式**（"税率"是赛题解析 §4.1 的误记）。而报价决策模型有 `unit_cost_cny / markup_rate / recommended_unit_price / line_total` 四个数。

需要一张映射表定死：`金额`是单价还是行小计？`销售总价（元）`是行小计还是总计（模板里另有"总金额（大写/小写）"和 `￥___元`，重复了）？"未计入税/运费/汇率"只能落在 `备注`（r8）——方案 §8.3 要求的"未计入必须显式暴露"目前没有落点。建议直接以"备注行 + 附录说明"落地，别等 P4。

### 4.2 必填 / 可空字段没有定义，而数据里天然为空

- B/E 的 `询价产品要求` 整列为空；B 的 `优先级` 6/21 为空；D 的内嵌表也有空优先级；PDF 的 `Condition` 列全空。
- 按 VALID-001 现在的写法（"缺少 Part Number、Quantity 等字段时生成问题项"），实现者会把这些也报缺失，全表刷屏。
- 建议：给每个字段一张 `required / optional / conditional` 表，并把"客户未要求 ≠ 不满足 ≠ 缺失"三种语义分别映射到 `pass / not_applicable / unknown`（三态设计已有，缺的是字段清单）。

### 4.3 "内部库存优先"这个待决策项的实际影响面比文档描述小

- 内部表与供应商表料号集合 100% 相同（163 = 163），所以该决策**不改变覆盖率**，只改变成本取数与库存可用性。
- 实测 B 案例内部库存可足量满足（stock ≥ qty 且件状 FN）的只有 **5/21 行**；另有 23 行库存为 0（且这 23 行的"库存件状"恰好同时为空，语义自洽）。
- 结论：这条 TBD 可以很快拍板，不必留到最后；建议默认"内部优先 + 不足则外部 + 跨表取更低价需记录理由"。

### 4.4 汇率方向其实已经可以定稿

实测 `汇率到CNY` 只有三个值：CNY=1（118 行）、EUR=7.75（84 行）、USD=7.1（140 行），单列、方向无歧义。计划 §3 把"汇率方向"列为待明确项，属于过度保守，建议直接写进数据字典，减少一个 TBD。

### 4.5 附件去重已在素材中真实发生

两份 EML 内嵌的 `Quote.pdf` 与 `附件/Quote.pdf` **二进制完全相同**（SHA 相同），且文件名相同。计划 §1 已识别"仅按文件名关联可能混用"，方向正确；P1 可以直接拿这两对文件做去重回归。

## 5. 文档卫生与一致性问题

1. **路径错误**：赛题解析 §1 写素材在 `F:\Codex\MatrixNEXT\询价信息素材`，该路径不存在；实际在 `rfq-agent\data\询价信息素材`。`refer_doc` 内的三份文档还引用了 `./RFQ_REQUIREMENTS_BACKLOG.md`，但 BACKLOG 未复制进 `refer_doc`，是死链。
2. **"税率"误记**：赛题解析 §4.1 称模板含"税率"，实测不存在（详见 4.1）。
3. **状态机漂移**：方案 §6.1 定义 9 个状态，骨架代码只有 `received / analyzed / needs_review` 三个；计划 §3 要求的 `policy_version`、`data_snapshot_id` 在 `Task` 里还没有。建议把 §6.1 标注为"目标态"，否则验收时对不上账。
4. **测试的环境依赖**：4 个用例本身在跑（`Ran 4 tests`），但在受限运行环境下 `TemporaryDirectory.cleanup` 里的 `os.chmod` 被拒绝（我实测在仓库内新建目录 chmod 直接 `WinError 5`），表现为 8 个 error。这不是断言失败，但会让人误判为代码坏了。建议测试根目录改成可注入（`RFQ_TEST_ROOT` / `TMP`）。
5. **P0 工时偏紧**：4–6 小时要覆盖"素材清单 + 两张表字典 + C 人工黄金数据 + Genesis 往返 + 入口验证"。仅本次（无人工逐字段标注）就做了覆盖率、PDF 抽文本、EML 结构、模板字段四轮实测。C 只有 7 行尚可，**A 的 122 行人工标注会明显超预算**。建议黄金数据分层：B/C 全量 + A/D 抽样 20 行。
6. **A/D 的规模风险未标注**：A/D 各 122 行，比 B/E（21 行）多 5 倍，且 A 无分隔符。文档只说"长表格抽取"，没提示 A 恰是最长且最难的一例。
