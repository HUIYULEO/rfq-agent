系统分层架构图 数据流图 处理流（端到端管道） Task 状态机 Agent 工作流 复核循环时序图

一 · 系统分层架构图

接口层（web / cli / 对话 / Deep Agents 适配）→ 服务层 RFQService → 确定性引擎层 → 解析与导出层 → 数据层，两侧是素材与 runtime 存储。箭头即真实调用方向；「数字唯一来源」在引擎层，模型永远在门外。

二 · 数据流图

从素材到产物的完整数据通道：.eml 四种载体归一为带 evidence 的 RFQ 行；参考表按 sha256 指纹一次性 sync 成 SQLite 快照；定价引擎纯函数出逐行结果；复核项与裁决构成闭环；三条出口——task.json、草案 JSON/DOCX、页面与模型视图。

三 · 处理流（端到端管道）

从收件到导出的完整管道：解析 → 建任务 → 分析 → 逐行定价 → 复核门 → （人工 / auto_draft 裁决循环，每次回答 revision+1 后局部重定价）→ 导出。全案无一行有价时收敛为一个 RI-TASK 整案问题；改数量则回炉 received 重跑。

四 · Task 状态机

Task.status 的五种状态（received · analyzed · awaiting_review · draft_ready · exported）与迁移事件。awaiting_review 的自环承载「一问一答重定价」与「先落草案产物但状态不变」两种语义；auto_draft 只会按默认选项闭环，不会放宽任何约束。

五 · Agent 工作流

genesis.Session 的对话工具循环：模型每轮只能选 dispatch 的 7 个工具之一，工具答案全部来自确定性核心；载荷压缩 ≤6000 字节防 122 行轰炸，6 轮上限防死循环，未配置时降级为提示+按钮流程照常。右上角是 agent.py 的 Deep Agents 平行栈。

六 · 复核循环时序图

一次典型阻塞复核的时序：按钮直答与对话转答是两条等价入口，resolve 之后纯函数重放（未放松的行结果逐位一致），revision+1 进入导出。模型在链路里只负责转述选项，不生成任何数字。
