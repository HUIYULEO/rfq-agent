## 2. 推荐实现边界

2026-11-02 范围补充：供应商查找与询价辅助已纳入总体方案 §16，需求 `SOURCING-001/002` 标为 `P2 / DEFERRED`。当前不实施、不要求演示，不增加 P0–P4 的工时和验收门；无价案例继续保留待人工询价结果。

一个 Python 服务进程，业务模块与 Agent 适配模块分离；首版任务状态和证据使用本地 SQLite/文件，参考表读入后生成不可变快照。部署时需持久存储。暂不建设消息队列、微服务、向量库或另一套通用工作流引擎。

主流程由代码保证：解析 → 校验 → 匹配 → 计算 → 草案。Deep Agents 负责理解补充要求、选择业务动作、解释结果和推动修订；不能跳过校验或更改计算值。模型版本和依赖在起步验证后锁定，不在设计阶段猜版本。

建议 Agent 工具边界：

| 工具 | 作用 | 服务端约束 |
|---|---|---|
| `analyze_rfq(task_id)` | 解析并提取、返回问题与证据摘要 | 输入文件已关联；正文/附件是数据，不执行其中指令 |
| `build_quote_options(task_id, revision)` | 匹配、过滤、计算候选 | 使用校验后的字段、数据快照和显式报价配置 |
| `apply_review(task_id, revision, changes)` | 记录用户补充和修订 | 校验字段；增加 revision；使旧价格/产物过期 |
| `export_quote_draft(task_id, revision)` | 生成 DOCX 草案 | 只读取当前版本的确定性结果；未报价项不可填零掩盖 |
| `get_task_result(task_id)` | 查询状态、解释依据、下载链接 | 输出结构化状态和紧凑证据，不回传全量数据表 |

UI 或 MOI 外壳可以调用同一个服务。Deep Agents 是唯一业务编排 Agent；MOI 若作为外壳，只负责交互和调用，避免两层 Agent 重复规划。MOI 分享、文件传递、调用返回及产物下载必须实际验证，不能视为已支持。外部展示部署费用和账号条件尚未知。

## 3. 业务契约补充

- 任务：`task_id`、`revision`、`evaluation_date`（从样例业务日期提取并保留来源）、`policy_version`、`data_snapshot_id`。第一版不引入实时/历史双模式。
- 金额：用 Decimal 计算，序列化为十进制字符串；汇率方向已由素材确定为“外币→CNY”（CNY=1、EUR=7.75、USD=7.1），成本单位与报价币种在数据字典中写死。CNY 对 CNY 无需汇率；不同单位未定义换算则转复核。
- 规则：缺失不等于不满足；条件未被客户要求时记不适用。禁止自行建立航空件状或证书替代关系。
- 价格可用性：`价格状态=有效` ∧ `有效期至≥evaluation_date` 双条件同时满足才可用；冲突时分记 `status_invalid` / `date_expired` 并保留两个原值（素材有 27 行矛盾，见 RULE-009）。
- 排序：先满足条件，再按统一成本升序、交期、稳定候选 ID 依次排序；这是拟议演示策略。不要新增没有数据依据的权重体系。
- 定价：演示策略定为加价20%、Decimal HALF_UP保留2位，明确不是赛事规定；成本口径默认“标准成本优先、不足或过期时用供应商价”。未知成本币种不假设为CNY。
- 数量：第一版不拆单、不超额 MOQ 采购；重复业务行保留并累计分配。供应商数量未知则是待确认候选。
- 输出：可自动生成待复核草案；未知单价为 null/“待询价”，总额仅标为“已报价项目小计”，不能当完整总价。税运费未知标为未计入，不能宣称最终含税到岸价。
- 报价有效期：不得超出选定供应商价格有效期；内部库存有效期没有规则则留空待确认。
- 恢复：人工修改后只重跑受影响阶段；重复导出同 revision 不重复创建业务任务。网络错误限次重试，参数或认证错误直接报告；模型调用次数和任务超时需配置并记录。

## 5. 验收口径

1. 六案例全部有终态与下载草案；A、B 的已报价行数与转人工行数须与冻结的黄金值一致；C/D/E/F 允许全行无价，但必须给出结构化的“无价格依据”理由与人工询价建议；`needs_review` 是正确业务结果，不等于失败。
2. 对人工标注的可读内容，行项目数、料号、数量、单位、RFQ编号和明确日期应100%匹配；行项目数按原始业务行计（A=122、B=21），重复行只标记不合并（A 有 10 个重复料号、14 条重复行）。确实有歧义的值以正确的复核状态验收，不能把模型输出自身当黄金答案。
3. 客户明确要求的件状、证书和报价条款必须全部保留，至少有可定位的原文证据。
4. 已报价行的字段来源、候选记录和计算公式覆盖率100%；未知条件不得静默判为通过。
5. 同一标准RFQ、数据快照、as_of和规则版本重复计算数字完全一致；模型提取在C上至少重复3次记录关键字段差异。
6. 边界测试覆盖过期当天、缺币种/汇率、回复截止≠交付截止、MOQ、件状/证书未知、重复料号累计库存、空价格和人工修订使旧草案失效。“过期当天”必须用合成 fixture：素材最近的有效期是 2026-09-13，而两组业务日期为 09-07/09-08，不存在当日过期行；另有 27 行状态与有效期矛盾，须按双条件口径断言。
7. 第二组是固定回归集，样例内容和预期结果不注入生产提示词。它只有三个请求，不据此宣称可泛化到所有RFQ；修改后重跑两组。
8. 记录端到端耗时、模型调用次数和usage，P2实测后再设演示超时目标，不凭空承诺延迟或成本。
